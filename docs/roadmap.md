# Этапы разработки

Исходный список функций слишком велик для одного MVP. Делим на этапы так, чтобы каждый уже приносил бизнесу измеримую пользу. Модель данных проектируется сразу с запасом на следующие этапы (курсы, ресурсы, филиалы, оплаты), чтобы потом не переделывать схему.

## MVP: «бот записывает и напоминает»

Цель: мастер-одиночка или маленький салон заменяет запись в мессенджере ботом и видит меньше неявок.

**Платформа**

- Платформенный бот: регистрация владельца, инструкция BotFather, подключение токена (`getMe`, `setWebhook`, `setMyName`, `setMyDescription`, `setMyCommands`).
- Мультитенантный вебхук-шлюз, aiogram-диспетчер на все боты, шифрование токенов.
- Обработка отозванного токена и заблокированного бота.

**Ядро**

- Один филиал, часовой пояс филиала.
- Каталог: категории, услуги, цена, длительность, буфер. Шаблоны каталога по типу бизнеса.
- Мастера: профиль, фото, услуги, индивидуальные цена и длительность.
- Графики: шаблоны и исключения (отпуск, больничный, блокировка времени).
- Движок слотов с тестами, удержание слота, защита от двойной записи в БД.
- Статусы записи: удержание, записан, подтверждён, пришёл, выполнено, не пришёл, отменён. Журнал событий.

**Клиент**

- Регистрация: имя, телефон через `request_contact`, согласие на обработку данных.
- Запись в чате (FSM + inline): каталог с ценой и длительностью, выбор мастера или «любой мастер», выбор слота, сводка, подтверждение.
- Мои записи: перенос и отмена с дедлайном (кнопки в чате).
- Уведомления: подтверждение записи, напоминания за 24 ч (с кнопкой «Подтверждаю») и за 2 ч, тихие часы.
- Deep links к мастеру и услуге.

**Персонал**

- Менеджер в чате: лента дня по мастерам, ручная запись (в том числе офлайн-клиента), перенос и отмена, каталог, мастера, графики, настройки бренда и правил — через меню и FSM.
- Мастер: мой день (карточки с inline-статусами «пришёл / не пришёл / выполнено»), блокировка времени.
- Базовый форс-мажор: отметка недоступности, автоматические варианты для клиентов, список нерешённых.
- Уведомления персонала о новых записях, переносах и отменах.

**Инфраструктура**

- Docker Compose, PostgreSQL, Redis, воркеры, S3, Sentry, бэкапы, CI с тестами.
- Хостинг в РФ.

**Критерий готовности:** 5–10 пилотных бизнесов принимают реальные записи через бота в течение месяца, доля неявок измерена до и после.

## V1: «бот возвращает клиентов и считает деньги»

- Отзывы и рейтинги: запрос после визита, ответы бизнеса, модерация, сигнал о плохой оценке, переход на Яндекс.Карты / 2ГИС.
- «Пора снова» по интервалу каждой услуги.
- Лист ожидания с автоматическим предложением освободившегося слота.
- Курсы и абонементы: шаблоны, прогресс, выбор следующего сеанса у того же мастера, гибкие курсы для тату.
- Акции, промокоды, сегменты, рассылки с ограничением частоты, отдельное согласие на маркетинг.
- Финансы: факт оплаты, способы оплаты, чаевые, схемы выплат мастерам, начисления, отметка «выплачено», отчёты, экспорт в Excel.
- Карта клиента: заметки, фото «до/после», портфолио мастера.
- Дайджесты и настройка уведомлений персонала по уровням важности.
- Роли ресепшена и журнал аудита в интерфейсе.
- Напоминание за 30 минут, запись за другого человека, групповая запись.
- Подписка и биллинг в платформенном боте, тарифы, льготный период.

## V2: «рост и масштаб»

- Онлайн-предоплата и депозиты (Telegram Payments + ЮKassa), правила для клиентов с неявками.
- Лояльность: бонусы, каждый N-й визит, день рождения, реферальная программа.
- Несколько филиалов, ресурсы (кабинеты, аппараты), цепочки услуг у разных мастеров.
- Импорт данных из YCLIENTS, DIKIDI, Excel.
- Синхронизация с Google Calendar для мастеров.
- Веб-версия кабинета для ресепшена на компьютере.
- ИИ-ассистент: запись на естественном языке («запиши меня в пятницу после шести к Ивану»), ответы на частые вопросы о салоне.
- Telegram Business: бот отвечает клиентам в личном аккаунте владельца.
- SMS-напоминания для клиентов без Telegram.
- Мультиязычность (EN, KZ, UZ) и выход на рынки СНГ.
- Отдельный инстанс для сетей (Enterprise).

## Основные риски

| Риск | Как снижаем |
| --- | --- |
| Бизнесу сложно создать бота в BotFather | Подробная инструкция с видео, помощь поддержки, в перспективе — помощь в настройке «под ключ» |
| Клиенты не переходят в бота | Материалы для запуска (QR, тексты), deep links, ручная запись офлайн-клиентов, чтобы бизнес не вёл две системы |
| Ошибки в расчёте слотов подрывают доверие | Изолированный модуль с большим набором тестов, ограничения БД против пересечений |
| Блокировки Telegram или ограничения рассылок | Строгие лимиты, разделение сервисных и маркетинговых сообщений, запасной канал (SMS) в V2 |
| Бесплатные конкуренты | Фокус на бренде и измеримом снижении неявок, удобство Telegram-first |
| Требования 152-ФЗ | Хостинг в РФ, договор-поручение, согласия, проверка юристом до запуска |
